# 同频 · 组队实验室

独立入口 `lab.html`，参考 sm-test 的逐题选择和即时反馈，使用 UI/UX Pro Max 的 Swiss/minimal、渐进披露、进度反馈、键盘和 reduced-motion 指引。视觉采用纸白 `#f6f5ef`、深绿 `#203e33`、亮黄 `#d6f37c`，系统中文字体；无外部字体、图片、框架或构建依赖。

## 用户路径

开始 → 9 组选择 → 确认选择与公开开关 → 后台推荐真实用户 → 现有私聊。

单选带短暂反馈后前进，多选显式继续。支持返回、修改、账号隔离草稿；入门能力与已有能力互斥。兴趣和标签为软排序依据，不设置匹配分数阈值，不展示虚假精度的百分比。

v2 题型：组队意向（最多 3 项）、专业方向（最多 3 项）、兴趣（最多 4 项）、能力（最多 12 项）、目标比赛（最多 10 场）和伙伴偏好（最多 4 项）均为多选；年级、最高经历阶段、每周总投入时间为单选。“还没决定”与具体比赛互斥，“我还在入门”与具体能力互斥。旧版四个单选字段在读取时转为单元素数组，不清空草稿、不批量改写数据库。共同比赛按交集解释；多选偏好和双重组队意向不会重复累加各自的权重。

## 数据与公开范围

问答独立存于新增 `lab_profiles`，不覆盖原有个人画像，不自动发布招募。公开默认关闭，用户明确开启后才进入实验室候选池。候选池仅包括主动公开实验室名片或仍在公开招募的用户，去重并排除自己。暂停实验室名片不会结束原有公开招募，也不会删除私聊。

匹配和标签解释位于 `server/lab-matching.js`；浏览器仅负责选择、草稿和结果呈现。`lab-catalog.js` 是前后端共用的选项字典。校验所有枚举、数组长度和入门选项互斥，联系方式沿用会话参与者鉴权。联系时再次检查公开状态，不凭用户 ID 绕过公开范围。

## 验证

`cd server && npm run build`；`npm run test:lab` 在有既有 better-sqlite3 依赖的环境运行。测试使用独立临时数据库和端口，不连接生产数据。人工浏览器验证单选、多选上限、返回编辑、访客流程和窄屏。
